# Agent rules — Kuvexta Odoo Foundation

- Target/default branch for Odoo 19 work: `19.0`.
- Foundation is the lowest reusable Kuvexta addon layer. Keep contracts small, stable and business-neutral.
- Hard **and hidden optional** dependencies may resolve only to official Odoo or Foundation. Do not bypass the boundary with dynamic imports, assets, model references, `env[...]`, `env.get(...)`, provider hooks or other soft coupling.
- If a feature requires Professional, Community/AGPL, Vendor Adapters, Internal or unresolved Review code, keep it out of Foundation and place the integration in an explicit bridge in the appropriate higher layer.
- Preserve every third-party copyright/license/notice and binary exactly when required. Never copy purchased vendor source or AGPL implementation into Foundation.
- Expected addon license is LGPL-compatible; physical migration must preserve the effective source license. Repository visibility is never license evidence.
- `MIGRATION_MANIFEST.json` is the physical-state contract. Every physical addon must have a machine-readable receipt whose module, source repository, source/target tree identity, effective license and source-deletion state agree with the checked-out addon.
- Initial migration requires exact tree equality and `source_deleted=false`. New receipts explicitly record `relicensing=false`; legacy schema-1 receipts may omit that field but may never assert relicensing.
- If Source is refactored/split before migration, the receipt must reference the exact post-split source commit/tree actually copied.
- Generated artifacts are regenerated by their declared generator, never approximated manually.
- Add/update tests for behavioral changes and keep dependency/receipt boundaries machine-checkable.
- Immediately before merge, re-fetch PR HEAD and base, verify required gates are green on that exact HEAD, and use squash plus an expected-head guard for automated merges. Base movement requires retest.
